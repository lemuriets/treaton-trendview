# TrendView_IVL

## Назначение
TrendView_IVL предназначен для декодирования и парсинга бинарных логов респиратора.  
Парсер извлекает данные устройства с временными метками из циклического бинарного хранилища и предоставляет эффективный доступ к данным по диапазону времени.

---

# Формат хранения бинарных логов

## Общие правила
- Логи хранятся в файлах с именами `00`–`07`
- Все файлы находятся в одной директории
- Количество файлов может быть меньше 8
- Размер каждого файла фиксирован: `2 GB`
- Файлы всегда должны обрабатываться строго последовательно:

```text
00 -> 01 -> 02 -> ... -> 07
```

- Данные логов непрерывны между файлами
- Когда все файлы полностью заполнены, запись начинает перезаписывать старые данные, начиная с файла `00` (поведение кольцевого буфера)

---

## Внутренняя структура файлов
Каждый лог-файл разделен на буферы фиксированного размера:

```text
buffer_size = 2^15 bytes (32768 bytes)
```

Примечания:
- Буферы могут быть заполнены не полностью
- Последний буфер в файле не гарантированно завершен
- Логика парсинга должна корректно обрабатывать частично записанные буферы

---

# Формат индексного файла (v2)

## Структура

### Заголовок
Первая строка содержит:
- версию формата индексного файла
- имя исходного бинарного файла

Пример:

```text
v2|00
```

---

### Строки данных
Каждая последующая строка содержит:

```text
(buffer_number, offset_inside_buffer, date, time)
```

Пример:

```text
1523,4096,2026-05-16,14:23:11.125
```

Описание:
- `buffer_number` — индекс физического буфера внутри бинарного хранилища
- `offset_inside_buffer` — смещение в байтах внутри буфера
- `date/time` — временная метка синхронизированного пакета

---

# Этапы парсинга

## 1. Генерация индекса (опционально)
Если индексный файл отсутствует:
- парсер генерирует индекс на основе пакетов `IdSynchro`
- сгенерированный индекс сохраняется в `.txt` файл

Назначение:
- избежать полного сканирования бинарных файлов при каждом запуске
- ускорить поиск данных по времени

---

## 2. Загрузка индекса
Парсер загружает индексный файл в память и:
- валидирует формат
- преобразует записи во внутренние структуры
- разделяет записи на логические сессии

Сессия — это непрерывный хронологический сегмент данных.

---

## 3. Чтение данных по диапазону времени
Парсер извлекает бинарные пакеты, используя:
- диапазон времени
- смещения из индекса
- границы сессий

Цель:
- эффективно извлекать только нужные фрагменты логов без полного сканирования файлов

---

# Известные проблемы и пограничные случаи

## Проблемы индекса

### 1. Перезапись кольцевого буфера
Из-за циклической структуры хранения:
- хронологический порядок внутри физических файлов может нарушаться
- новые данные могут располагаться раньше старых
- парсер должен корректно восстанавливать логическую временную последовательность

### 2. Неполные буферы
Последний записанный буфер может содержать:
- частично записанные пакеты
- поврежденные или незавершенные записи

Парсер должен безопасно пропускать некорректные данные.

### 3. Разделение на сессии
Большие временные разрывы или границы перезаписи могут создавать:
- разорванные сессии
- откат временных меток назад

Логика определения сессий должна учитывать такие случаи.

### 4. Отсутствующие файлы
Некоторые файлы из диапазона `00`–`07` могут отсутствовать.

Парсер должен:
- корректно обрабатывать отсутствие файлов
- сохранять последовательный порядок существующих файлов

# Требования к парсеру

- Высокая производительность на больших объемах данных
- Минимальное количество аллокаций памяти
- Быстрый поиск по диапазону времени
- Безопасная обработка поврежденных или неполных бинарных данных
- Корректное восстановление временной последовательности в циклическом хранилище
- Поддержка инкрементального пересоздания индекса
